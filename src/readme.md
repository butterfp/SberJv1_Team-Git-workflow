# TASK 4
## Правила работы с переводами строк (Line Endings)

### В чём разница между LF и CRLF?
В разных операционных системах конец строки в текстовых файлах обозначается разными управляющими символами:
* **LF (`\n`, Line Feed)** — перевод строки на одну позицию вниз. 
* Используется по умолчанию в **Linux** (включая SberOS) и **macOS**.
* **CRLF (`\r\n`, Carriage Return + Line Feed)** — возврат каретки в начало строки и перевод строки вниз. 
* Используется по умолчанию в **Windows**.

### Зачем это контролировать?
Если один разработчик на Windows сохранит файл с `CRLF`, а другой на Linux — с `LF`, Git посчитает, 
что изменились **все строки файла**. 
Это делает код-ревью невозможным и приводит к лишним конфликтам при слиянии веток.

### Стандарт в проекте и настройка Git
Единый стандарт хранения текстовых файлов в удалённом репозитории — **LF (`\n`)**.

Для автоматической конвертации при работе с репозиторием каждый разработчик должен выполнить настройку:

* **Для Windows** (при получении кода ставит `CRLF`, при отправке в репозиторий конвертирует обратно в `LF`):
  ```bash
  git config --global core.autocrlf true
