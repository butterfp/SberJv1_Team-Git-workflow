# TASK 4
## Правила работы с переводами строк (Line Endings)

### В чём разница между LF и CRLF?
В разных операционных системах конец строки в текстовых файлах обозначается разными управляющими символами:
* **LF (`\n`, Line Feed)** — перевод строки на одну позицию вниз. 
* Используется по умолчанию в **Linux** (включая SberOS) и **macOS**.
* **CRLF (`\r\n`, Carriage Return + Line Feed)** — возврат каретки в начало строки и перевод строки вниз. 
* Используется по умолчанию в **Windows**.

### Зачем это контролировать?
Если один разработчик на Windows сохранит файл с `CRLF`, а другой на Linux — с `LF`, Git посчитает, 
что изменились **все строки файла**. 
Это делает код-ревью невозможным и приводит к лишним конфликтам при слиянии веток.

### Стандарт в проекте и настройка Git
Единый стандарт хранения текстовых файлов в удалённом репозитории — **LF (`\n`)**.

Для автоматической конвертации при работе с репозиторием каждый разработчик должен выполнить настройку:

* **Для Windows** (при получении кода ставит `CRLF`, при отправке в репозиторий конвертирует обратно в `LF`):
  ```bash
  git config --global core.autocrlf true


# Задание 10. Разделение, объединение и переименование коммитов

Все операции выполнены в консоли Git в отдельной ветке `feature/TASK-10-console`.

### 1. Создание коммитов с расчётом процентов

Добавлен метод `percentage()` для расчёта процентов, после чего создан отдельный коммит:

```bash
git add src/test/src/main/java/org/butterfp/test/CalculatorController.java
git commit -m "TASK-10 Добавить расчет процентов"
```

Затем добавлены unit-тесты и создан второй коммит:

```bash
git add src/test/src/test/java/org/butterfp/test/CalculatorControllerTest.java
git commit -m "TASK-10 Добавить unit-тесты расчета процентов"
```

### 2. Объединение двух коммитов (squash)

Для объединения двух последних коммитов использована команда:

```bash
git rebase -i HEAD~2
```

В открывшемся редакторе у второго коммита команда `pick` заменена на `squash`.

После сохранения изменений два коммита были объединены в один:

`TASK-10 Добавить расчет процентов и unit-тесты`

### 3. Создание коммита с функциональностью памяти

В контроллер добавлены поле `memory` и методы `saveToMemory()` и `readFromMemory()`.

Изменения сохранены одним коммитом:

```bash
git add src/test/src/main/java/org/butterfp/test/CalculatorController.java
git commit -m "TASK-10 Добавить сохранение и чтение значения из памяти"
```

### 4. Разделение одного коммита на два

Для разделения коммита использован интерактивный rebase:

```bash
git rebase -i HEAD~1
```

В редакторе команда `pick` заменена на `edit`.

После остановки rebase выполнен сброс последнего коммита с сохранением изменений в рабочей директории:

```bash
git reset HEAD~1
```

С помощью интерактивного добавления изменений в индекс выделен код сохранения значения в память:

```bash
git add -p
git commit -m "TASK-10 Добавить сохранение значения в память"
```

Затем оставшиеся изменения добавлены во второй коммит:

```bash
git add src/test/src/main/java/org/butterfp/test/CalculatorController.java
git commit -m "TASK-10 Добавить чтение значения из памяти"
git rebase --continue
```

В результате один коммит был разделён на два независимых коммита.

### 5. Изменение порядка коммитов

Для изменения порядка трёх коммитов выполнена команда:

```bash
git rebase -i HEAD~3
```

В редакторе коммиты расположены в следующем порядке:

```text
pick <hash> TASK-10 Добавить сохранение значения в память
pick <hash> TASK-10 Добавить чтение значения из памяти
pick <hash> TASK-10 Добавить расчет процентов и unit-тесты
```

При выполнении rebase возникли конфликты в файле `CalculatorController.java`. Конфликты разрешены вручную с сохранением всех необходимых методов.

После каждого разрешения конфликта выполнялись команды:

```bash
git add src/test/src/main/java/org/butterfp/test/CalculatorController.java
git rebase --continue
```

После завершения rebase история проверена командой:

```bash
git log -4 --oneline
```

Полученный порядок коммитов:

```text
3ebbeaa TASK-10 Добавить расчет процентов и unit-тесты
509791e TASK-10 Добавить чтение значения из памяти
eee4fcc TASK-10 Добавить сохранение значения в память
c308759 Merge branch 'feature/TASK-7-trigonometry' into 'develop'
```

Таким образом, функциональность памяти располагается в истории раньше расчёта процентов.
